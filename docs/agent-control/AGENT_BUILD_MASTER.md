# Agent Build Master

Status: AI-agent build control document. This file is execution authority for coding agents. It does not replace `docs/brain-readable-concept-manual.md`; it turns that source reference into build control.

## What the Brain is

The Brain is an event-sourced, self-rewiring cognitive runtime that preserves the full compiled Brain scope: commercial intelligence, source sensing, belief updating, memory systems, formulas, algorithms, theories, dashboards, fixtures, tests, governance, and future cognitive layers.

## What the Brain is not

The Brain is not a chatbot wrapper, CRM clone, static dashboard, generic scraper, or V0-only prototype. It is not allowed to claim human-brain equivalence, consciousness, or completion without implementation and acceptance evidence.

## Canonical source hierarchy

1. User doctrine and explicit user instructions.
2. Canonical extraction artifacts and concept matrices.
3. `docs/brain-readable-concept-manual.md` as source-readable reference.
4. `docs/spec/*` as agent-executable specification.
5. Existing code, tests, migrations, and runtime docs.
6. Contaminated or derivative synthesis packages only as reference.

If sources conflict, preserve both and log the contradiction unless a later explicit user instruction supersedes one.

## Build phases

- V0: proof harness and executable cognitive loop.
- V1: commercial money spine.
- V2: advanced cognition, memory, reasoning, and learning.
- V3: digital organism architecture.
- V4: research and consciousness-adjacent expansion.

V0 is not the whole Brain.

## Current build target

Build the agent-executable substrate in order: schemas, formulas, runtime loops, fixtures, tests, acceptance reports, then dashboards. Do not add live ingestion or external actions before approval gates and replay tests exist.

## Allowed agent actions

- Create schemas, services, tests, fixtures, docs, migrations, and reports.
- Propose implementation tickets.
- Draft internal-only simulations.
- Update internal belief, graph, memory, and score state under tests.
- Record assumptions, blocked work, contradictions, and gaps.

## Prohibited agent actions

- Narrow scope.
- Delete speculative or future concepts.
- Claim completion without tests.
- Add autonomous spending.
- Add autonomous external outreach.
- Bypass approval gates.
- Create formula outputs without formula-run trace.
- Learn from outcomes without attribution.

## GO/HOLD conditions

GO requires implementation, fixtures, deterministic replay, passing tests, and acceptance evidence for the claimed scope. HOLD applies if any schema, formula, state machine, fixture, replay, approval gate, attribution rule, or acceptance report is missing.

## Escalation rules

Escalate to Tyler when scope conflict, legal risk, data deletion, external action, spending, user identity, source authority, or contradictory doctrine cannot be resolved from canonical documents.
